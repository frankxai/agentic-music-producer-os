# Music Regulators

Active operational contract — reviewed 2026-10-09. Apply gates only at the stage they regulate. A regulator records a decision with evidence; it is not an artistic score or a claim of legal clearance. Historical research and dated provider tables are inputs, never current operating authority.

| Regulator | Trigger | Required evidence | Decision on missing evidence |
|---|---|---|---|
| Meaning | Draft | Listener moment, emotional intention, focal idea | Make a reversible artistic assumption; avoid interrogation |
| Output contract | Draft/adapter | Requested format, approved exact text, mode | Preserve user text and requested scope; do not expand into full lyrics |
| Craft | Revision | Specific line, motif, section or audible moment against brief | Recommend one mechanism and one audition; subjective scores optional |
| Capability | Execution | Current account/UI or official API model, mode, limits | Documented feature is not observed capability; hold unsupported execution |
| Spend | Paid action | Explicit bounded authorization, exact artifact hashes, expiry | Hold; edited inputs need renewed approval; uncertain submission needs reconciliation |
| Asset | Intake | Actual export, provider ID, content hash, capture method | Mark unrendered/unowned; never invent files or bypass approved downloads |
| Listening | A&R decision | Reviewer, actual playback, asset hash, timestamps and findings | Return text/prompt-only critique; no listened verdict |
| Technical | Mix/delivery | Measurement method, file hash, destination specification | Unknown values remain null; no universal loudness target |
| Rights | Release | Inputs/contributors, account and applicable terms, output/download provenance, permissions | Hold release; subscription tier alone is insufficient |
| Destination | Distribution | Current destination rules and version-specific metadata | Check chosen destination; no blanket distributor allow/block list |
| Publication | External release | Exact assets, audience/destination, operator instruction | Prepare reviewable package; publish only when authorized |
| Learning | Recap | Actual verdict/use report, context, failed/successful mechanism | Save scoped observation; do not promote one preference into global law |

## Evidence vocabulary

Label every material claim `documented`, `observed`, `measured`, `self_reported`, `hypothesis`, or `unknown`. Include source/ref, date and applicability. A prompt describes desired BPM; a measurement estimates delivered BPM. A provider completion is not listening. A selected winner is not a cleared release. A factual gate cannot be unlocked by a high taste score.

Use `KEEP`, `ITERATE`, `CUT`, or `HOLD` only with reviewer and review scope. A text reviewer may keep a prompt; an unheard recording stays unreviewed. Do not enforce a kill quota. Subtraction is a useful experiment, not a requirement to delete something from every arrangement.

Where they are unresolved, keep the package private and record a specific blocker. Never fabricate a training-data assurance the operator cannot substantiate.

## Session and team contract

Delegate a bounded task only when independent expertise improves the decision. Give the collaborator the brief and evidence needed for its scope; do not leak previous verdicts into a fresh listening pass. Each handoff includes artifact/hash, requested decision, scope and next owner. Finish with changed decisions, saved assets, unresolved holds and one next action. Suggested follow-up is not a running automation; schedules require an actual configured scheduler.
