# Music Taste Review

Read `docs/MUSIC-FUNDAMENTALS.md` and `docs/MUSIC-REGULATORS.md` from repository root. Name the reviewer, artifact/version, scope and evidence before judging.

For text/prompt: identify the intended listener effect, strongest specific choice, dominant failure and one mechanism to test. Check clarity, prosody, focus, coherence and requested format. Do not infer melody, pronunciation, emotional impact or mix quality from descriptions. Originality violations, contradictory/empty required instructions, fabricated facts and unsafe guidance block the relevant draft. Distinguish concrete blocks from subjective reservations.

For audio: require actual accessible playback and an asset hash. Review the opening, hook/motif, transitions, delivery, masking and ending using timestamps. Compare against its own brief. Preserve a useful accident. Give KEEP, ITERATE or CUT with rationale; use HOLD when playback/evidence is missing. Do not impose an instrument minimum, biggest-final-chorus rule or kill quota. Measurements need a method and file reference.

For schema-6 Simple sessions, write these exact lines in `review.md`, with real reviewer and specific evidence:

```text
SCOPE: prompt
REVIEWER: <name or agent identity>
EVIDENCE: <specific choice and coherence finding in the exact prompt>
VERDICT: PASS
HARD VETOES: none
```

Use REVISE or BLOCK when appropriate; validation then prevents execution. Optional ratings are subjective aids, never factual gates. The retained schema-5 Custom adapter still requires its legacy score/axis syntax (see `docs/SESSION-MODES.md`); that compatibility threshold is not a universal musical truth, audio review or release assessment. Do not invent axis findings to pass it.

Separate the next action from approval to spend or publish. Save exact changes and what a comparison should reveal. Release clearance requires the independent rights, destination and publication regulators.
